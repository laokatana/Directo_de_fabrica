# Project Roadmap

## Objetivo

Mantener una visión clara de la evolución técnica y funcional del proyecto.

El roadmap debe actualizarse cuando existan cambios significativos de alcance.

---

# Estado Actual

Arquitectura:

Frontend estático.

Tecnologías:

* HTML
* CSS
* JavaScript

Proceso de venta:

```text
Catálogo
→ Carrito
→ WhatsApp
```

---

# Fase 1 - Fundación

Estado: En progreso

Objetivos:

* Seguridad OWASP
* Accesibilidad WCAG AA
* Optimización SEO
* Refactorización de código
* Modularización

Entregables:

* AGENTS.md
* Architecture.md
* Security.md
* Accessibility.md
* Mobile-First.md
* SEO.md
* Backlog actualizado

---

# Fase 2 - Calidad

Objetivos:

* Tests unitarios
* Centralización de utilidades
* Mejora de mantenibilidad
* Optimización del carrito

Entregables:

* cobertura mínima de tests
* reducción de duplicación
* módulos reutilizables

---

# Fase 3 - Experiencia de Usuario

Objetivos:

* Dark Mode
* Optimización responsive
* Mejoras de navegación
* Optimización de formularios

Entregables:

* experiencia consistente en móviles
* mejora de accesibilidad
* mejor conversión

---

# Fase 4 - Performance

Objetivos:

* optimización de imágenes
* Core Web Vitals
* lazy loading
* reducción de recursos

Objetivos técnicos:

```text
LCP < 2.5s
CLS < 0.1
INP < 200ms
```

---

# Fase 5 - Escalabilidad

Opcional.

Solo si el negocio lo requiere.

Posibles tecnologías:

* Express
* FastAPI
* PostgreSQL
* Cloudinary

Objetivos:

* panel administrativo
* gestión de productos
* automatización de pedidos
* integración de pagos

---

# Principios de Evolución

Toda nueva funcionalidad debe:

* respetar AGENTS.md
* respetar Architecture.md
* respetar Security.md
* mantener compatibilidad móvil
* preservar accesibilidad
* evitar complejidad innecesaria

---

# Funcionalidades Futuras

Posibles mejoras:

* búsqueda avanzada
* filtros inteligentes
* panel administrativo
* integración Mercado Pago
* seguimiento de pedidos
* catálogo dinámico

---

# Fuera de Alcance Actual

No se consideran prioritarios:

* microservicios
* Kubernetes
* arquitectura distribuida
* múltiples bases de datos

Mantener la solución simple mientras el negocio lo permita.

---

# Criterios de aprobación

Toda evolución del proyecto debe:

* resolver una necesidad real
* mantener simplicidad
* mejorar experiencia de usuario
* respetar seguridad
* mantener escalabilidad futura
